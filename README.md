# 帆装配平与分级缩帆决策（古船模型帆索校准 v2）

在原「古船模型帆索校准」原型上增加：每艘船登记**各帆面面积、形心、缩帆档与复原力曲线**，
按**风向 / 风级**计算合力中心、风压力矩与危险（平衡）倾角，求同时满足**复原力**与
**纵向平衡**的**最小缩帆方案**，给出最大安全风级、原因和下一步作业。旧版帆索校准台账保留在页面底部。

## 运行

```bash
npm start            # http://localhost:3038 （PORT 可覆盖）
npm test             # 84 个单元/集成：算法、接口、并发、回滚、持久化、档位兼容、升级迁移、跨实例互斥、旧台账快照
npm run check:legacy # 旧台账真实回归（真实服务+重启+快照字节核对，临时库，不碰运行态）
npm run test:e2e     # Playwright 真实浏览器 5 个套件（安全/降档/无解/冲突、更新兼容、旧台账、升级迁移、双实例共享库）
```

数据布局（交付数据与运行时可写数据分离）：

- `data/delivery/legacy-snapshot.json` — **不可变交付快照**：原型交付时的旧版帆索校准台账（MR-001 的两条帆索任务与模型级日志）。帆装功能的启动、更新、测试都不会写入它，可用 `sha256sum` 核对。
- `data/runtime.json`（默认，可用 `DB_PATH` 覆盖）— 运行时可写数据库。
- `data/model-rigging-calibration.json` — **旧版（v1）数据文件**，升级时只读、不修改。

**升级启动按固定顺序选数据源**：

1. 运行时文件 `data/runtime.json` 存在 → 直接使用（即使旧文件也在，绝不重复导入，后续写入不被覆盖）；
2. 运行时文件不存在、仅旧文件存在 → 安全迁移：读取旧文件，逐字保留模型编号、任务、日志；已含帆装时连档位与版本一并保留，纯 v1 台账则补齐种子帆装；结果**原子写入**运行时文件（旧文件永不修改）；
3. 两处都没有 → 从交付快照播种。

迁移失败（旧库损坏/写盘中断）时旧文件保持原样可读、运行时文件不出现半截副本（临时文件随失败清理），修复后可重试。迁移成功后重启只沿用结果。`LEGACY_DB_PATH` 可指定旧文件（`DB_PATH` 自定义时默认不自动迁移）。

校验旧台账未被改写：`npm run check:legacy`（启动真实服务，逐字段比对编号/任务/日志，验证追加与写失败回滚后重启仍一致，且快照文件字节不变）。

## 模型

- 风压 `p = ½·ρ·v²`，v 取蒲福风级风速下限并乘阵风系数 1.3。
- 合力中心 = 各帆当前档位有效面积对形心的加权中心（含缩帆后的形心下沉）。
- 横倾力矩 `M = p·A_投影·z_CE`；复原力矩 `Δ·g·GZ(φ)`，GZ 按登记曲线线性插值。
- 稳定平衡（危险）倾角：`ΔgGZ(φ) = M·cos φ` 的首个交叉点；若到危险角仍无交叉即持续倾侧。
- 安全需同时满足：危险角前存在平衡角、危险角复原裕度 ≥ 安全系数、合力中心纵向位置在平衡范围内。
- 决策枚举所有「只加深、不跳档」的档位组合，按**档距最少 → 保留帆面积最大**排序取最小方案，
  并计算该方案的最大安全风级；最深档仍不安全则判 `infeasible` 并给出避风/调压载等下一步。
  决策返回 `feasible`：`safe` 与 `reef_required` 均为 `true`（当前已安全时 `solution=null`），仅 `infeasible` 为 `false`。

## 拒绝规则（422 / 409）

数据缺失、复原力曲线乱序或不过原点、未覆盖危险角、重复档、跳档（非 0,1,2…）、
缩帆系数不严格减小、作业指令一次跨两档（非法跳档）——一律 422 拒绝，不产生写入。
更新/作业必须携带 `expectedVersion`；过期版本（含重复登记同 code）409，后写不覆盖先写。

### 更新帆装定义时的档位兼容

船可能已收到末档，而新定义档数更少、复用帆面编号、增删帆面。`PUT /api/rigs/:code`
在校验通过后、同一写事务内按 `levelPolicy` 迁移旧 `currentLevels`（失败即整体丢弃，不部分落盘）：

- `clamp`（默认，确定性且可追溯）：
  - **减少档数**：越界旧档钳到新末档（如旧 3 档、新 0..1 → 置为 1）；
  - **复用帆面编号**：按同一面帆处理，按新档数钳制，不另建档位键；
  - **新增帆面**：初始化为 0 档（满帆）；
  - **移除帆面**：删除其档位；以上每条都记入响应 `migrations` 与帆装 `levelMigrations`/日志。
- `reject`：存在越界旧档，或要移除仍处于收帆状态（>0 档）的帆时，整体 422 拒绝，版本/定义/档位/文件均不变。

未知策略名返回 422（`LEVEL_POLICY_INVALID`）。迁移后所有档位都在新定义内，可正常逐级作业，记录不会锁死。

## 并发、回滚与持久化

- 进程内单写者队列 + **跨实例文件锁**（`src/file-lock.js`：`O_EXCL` 抢锁 + 轮询等待 + 死进程/损坏/超龄锁接管）：两个服务实例共享同一运行时库时，首次迁移只有一个实例执行，竞争者等待后直接复用结果，不重复导入。
- 乐观版本号 CAS：每次提交进入锁后重读磁盘最新版本，依据已过期（含两个实例按同一版本并发写）明确抛 409 `VERSION_CONFLICT`，后写绝不覆盖先写；失败实例刷新后可带新版本重试。
- 每个实例使用唯一临时文件名 `<库>.tmp-<pid>-<uuid>`；只在持锁时清理陈旧 tmp，绝不可能删掉另一实例正在写的文件。
- 写临时文件 + fsync + 原子 rename；任何校验/写盘失败都整体回滚，旧文件与可读运行时状态都保留。
- 重启后从同一文件恢复，版本与档位延续；损坏文件拒绝启动。

## 接口

| 方法/路径 | 说明 |
| --- | --- |
| `GET  /api/rigs` | 船只摘要列表 |
| `POST /api/rigs` | 新登记帆装（重复 code → 409） |
| `GET  /api/rigs/:code` | 完整帆装与当前档位 |
| `PUT  /api/rigs/:code` | 按 `expectedVersion` 更新帆装 |
| `GET  /api/rigs/:code/decision?beaufort=&direction=` | 分级缩帆决策（含原因、下一步、安全包络） |
| `GET  /api/rigs/:code/envelope?direction=` | 当前档位 0–12 级安全包络 |
| `POST /api/rigs/:code/reef` | 逐级缩帆/放帆作业 `{moves, expectedVersion}` |
| `/api/items*`、`/api/stats` | 旧版帆索校准台账（保留） |

页面含帆面中心侧视图（■ 帆面形心、× 当前合力中心、+ 建议合力中心、绿色纵向平衡带）、
各风级安全包络图（平衡倾角 vs 危险倾角），以及缩帆建议与逐级作业按钮。
